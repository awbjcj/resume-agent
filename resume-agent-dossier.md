# Project: Resume Agent

A local-first, fact-locked AI pipeline that pulls job postings from 16+ sources, scores them against a candidate's real experience, tailors resumes and cover letters through a multi-agent review loop, renders them to PDF, and tracks applications — shippable as a public multi-user web service with its own authentication, tenancy, and security-hardening layer, and built around a shared real-time streaming-conversation substrate that now powers a coaching chat, a mock-interview chat, and a conversational job-discovery agent.

## Summary

Job seekers waste hours manually rewriting a resume for each posting, and generic AI rewriters routinely fabricate experience the candidate never had. Resume Agent solves both: it ingests a person's resume (plus optional GitHub repositories) into a single `facts.json` "fact-lock," then treats that file as the only ground truth any downstream agent may draw from — agents rewrite and reframe, but a hard `fact-check` gate fails any bullet that cannot be traced to a real fact. The system is a full funnel (`pull → discover → approve → tailor → cover-letter → render → track`) exposed identically through a Typer CLI and a FastAPI + React web app. It began as a single-user local tool and was rearchitected into a multi-tenant service — per-user SQLite workspaces addressed through a `contextvars`-propagated tenancy context, email/Google-OAuth authentication, per-user and platform-wide LLM spend governance, and Gmail-based application-status tracking — then hardened through a self-authored threat model and security-best-practices audit that closed several cross-tenant trust-boundary gaps before public registration. Most recently, a provider-neutral token-streaming substrate (`AgentRunner.stream()`, resumable SSE) was built once and then reused to convert both the profile-coaching chat and the mock-interview chat to real-time streaming, and to replace four one-shot, duplicate discovery agents (source discovery + search-term discovery, each with a separate LLM-call pair) with a single conversational "Discovery Scout" that proposes sources and search terms with citations across a multi-turn chat while keeping every actual mutation behind a human-triggered approve/dismiss endpoint. Since then the platform-budget model was reworked from weighted-token estimates to immutable USD micro-cost accounting priced off effective-dated provider rate cards, and a durable, reconciliation-backed run-completion pipeline replaced a purely SSE-driven one so no progress bar or toast is ever permanently lost to a dropped connection. It was built and maintained by a single author across 1,900+ commits between 2026-06-08 and 2026-08-24 (`git log --format` authorship breakdown), and remains under active development. The codebase is ~67,000 lines of Python across 386 modules, backed by roughly 3,096 test functions across 421 files that run fully offline.

## Architecture highlights

- **Fact-lock invariant enforced by a closed schema.** Every tailored bullet must trace to `data/profile/facts.json`; the `fact-check` reviewer in `review.yaml` is a non-scored hard gate. `profile/project_extractor.py` uses a closed Pydantic boundary (`ProjectDocFacts`, `extra="forbid"`) that can emit exactly one project plus evidenced skills and _cannot_ fabricate employment or education.
- **Multi-tenant workspace isolation rides one propagation mechanism.** A `contextvars.ContextVar` (`tenancy/context.py`) holds the active per-request `UserContext` (settings, workspace paths, engine); it is set at exactly three points — the API auth dependency, the background-run worker wrapper, and the CLI callback — so every deeper call site reads `get_settings()`/`current_context()` instead of receiving a threaded parameter (`docs/adr/0003-contextvar-tenancy-propagation.md`).
- **One SSRF-safe egress gateway for every user-influenced URL.** `security/outbound.py::fetch_public_text` validates scheme/credentials, rejects any resolved address that is not globally routable, pins the TCP connection to the address it validated while preserving the original `Host`/SNI (defeating DNS-rebinding), and revalidates every redirect hop under a byte/content-type-bounded response. Every URL-fetching call site in the codebase (profile source intake, job/source URL ingestion, ATS HTML sniffing) was migrated onto this one function (`docs/adr/0008-...md`).
- **Tenant-confined artifact and render storage.** `tenancy/storage.py::artifact_path` is the only path a download route may resolve a stored PDF path through; in multi-user mode it raises rather than returns a path outside the tenant's own output directory — including a path restored from an imported workspace archive, which is validated and normalized before the atomic import swap completes.
- **Registration and shared-LLM-key eligibility are deliberately separate decisions.** `Settings.registration_mode` gates whether an account can be created; `User.shared_key_access` separately gates whether that account may spend the platform's shared provider keys, closing an audited Sybil-multiplication gap without requiring invite-only registration permanently.
- **Shared-key spend is metered in immutable dollars, not weighted tokens.** `tenancy/costs.py` and `tenancy/quotas.py` price every recorded token and native-search component against effective-dated per-provider/per-model rate cards; each non-admin holds an anchored tier period plus a durable credit balance, consumes allowance before credits, and is rejected only after a bounded in-flight overage is recorded. This supersedes ADR-0009's token-budget enforcement after a `shadow`-mode rollout (`docs/adr/0010-cost-based-llm-quotas.md`); BYOK calls retain cost telemetry but carry zero quota charge, and missing provider rates fail closed rather than charging an unpriced call.
- **Single provider seam with lazy imports.** `build_model()` in `llm_runner.py` is the only place that knows about concrete provider SDKs; provider-prefixed model ids (`openai:` / `gemini:` / `deepseek:`, bare = Anthropic) route each of three tiers independently, so a Claude-only run never imports the OpenAI or Gemini libraries.
- **Table-driven connector dispatch with per-URL failure isolation.** `discovery/connectors/companies.py` resolves each careers URL through `detect.py` (singleton → L1 URL pattern → L2 HTML sniff) and calls the matching backend; any URL that fails detection or errors is recorded on `FetchResult.failures` and never aborts the run. 16 ATS/board backends live in `discovery/connectors/`.
- **Deadlock-safe concurrent LLM fan-out.** Discovery and tailoring run pure-async siblings through `gather_isolated` (`concurrency.py`); a global `asyncio.Semaphore(llm_concurrency)` is acquired _only_ inside the leaf `llm_runner.acall`, so nested jobs×panel fan-out cannot self-starve.
- **Source priority is upgrade-not-drop.** When a canonical source re-finds an aggregator job, the existing `Job` row is mutated in place (same id) so tailored resumes, cover letters, and application status are never lost; the dedup key is paired with a location guard (`docs/adr/0001-...md`).
- **Self-authored threat modeling closed the loop before public rollout.** A source-based threat model and a companion best-practices report (`docs/resume-agent-threat-model.md`, `docs/security_best_practices_report.md`) enumerate trust boundaries, an attacker model, and a prioritized (P0/P1/P2) findings table; the P0 findings drove the egress-gateway, tenant-storage, canonical-origin, archive-extraction, and registration/budget-governance changes above, each captured in its own ADR. The best-practices report was authored to supersede the original threat-model document as the maintained release-gate reference (`git log` commit `53a155f3`).
- **One streaming substrate, three chat products.** `AgentRunner.stream()` (`llm_runner.py`) yields provider-neutral token/tool/reasoning events from Agno's stream regardless of provider; `sessions/stream.py::RunStreamSink` durably logs each event to an append-only NDJSON file and wakes process-local SSE subscribers, batching text and reasoning deltas on separate budgets so a word-at-a-time reasoning model can't flood the UI with one event per token. `sessions/turns.py` owns turn validation, formatter-boundary detection, and cooperative mid-stream cancellation shared by every caller. Built once for the Profile Coach and Mock Interviewer, the same substrate (`GET /api/runs/{id}/stream`, resumable from a durable byte offset) was then reused unmodified for the Discovery Scout chat — a spec explicitly sequenced so the streaming design (spec 1) shipped before the conversational agent that depends on it (spec 2, `docs/superpowers/specs/2026-08-01-*`).
- **Discovery Scout replaces four one-shot agents with one conversational agent, and keeps a hard write boundary.** `discovery/scout.py` collapses the former `source_scout.py`/`search_scout.py` research-agent pair (and the fire-and-forget `source_discovery.py`/`search_discovery.py` orchestrators they backed) into a single persona that proposes both companies-to-add and search-term refinements, each carrying a citation and a `check_source`-derived validation status, across a multi-turn chat that remembers prior rejections. The agent is asserted to hold **no write tool** — every mutation (`connectors.yaml` / `search.yaml`) happens only through a human hitting an explicit `POST .../proposals/{id}/approve` or `/dismiss` endpoint (`services/scout.py`, tested via a tool-name assertion on the built persona agent).
- **Curated single-skill agents with MCP access isolated to one read-only integration.** Each task agent is built against exactly one hash-pinned skill from a verified local registry, so skill identity, version, and hash become auditable run/artifact metadata instead of one model holding a large combined tool surface. H-1B sponsorship research is the only MCP integration in the codebase: a dedicated agent owns one prefixed, read-only `MCPTools` instance, runs only for sponsorship-required jobs whose posting is silent on the question, and its historical company evidence is structurally prevented from becoming a current-role sponsorship claim — every other agent consumes only that validated evidence and never receives raw MCP access (`docs/adr/0011-curated-skill-agents-h1b-only-mcp.md`).
- **SSE is a latency optimization, not the source of truth, for run completion.** Progress delivery was redesigned after five concurrency defects caused frozen progress bars and lost completion toasts in production: an unbounded-reconnect-with-backoff subscriber, a durable `announced_at` marker on the run snapshot with a locked read-modify-write (`api/runs/manager.py::mark_announced`), a widened `list_rehydratable` window so a terminal run is never unobservable, a `POST /api/runs/ack` endpoint, and a 15-second client-side reconciliation poller that guarantees eventual delivery independent of any single SSE connection's fate (`web/src/features/runs/use-rehydrate-runs.ts`, PR `#86`, commit `81022cf7`). Run lifecycle ownership also moved out of the transport layer (`sse.ts`) into a dedicated `tracker.ts`, closing a race where a completion toast could fire before its own query-invalidation had run.
